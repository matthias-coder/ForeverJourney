# ForeverJourney Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die statische Buch-Seite, die `data/index.json`, `data/<id>.json` und `shots/` aus dem Repo liest und als „Chronik der Ewigen“ auf GitHub Pages darstellt.

**Architecture:** Reines HTML/CSS/JS mit ES-Modulen, kein Build-Schritt. Reine Logik (Formatierung, Routing, Tagebuch-Text, Seitenaufteilung, Kartenpfade) liegt in Modulen ohne DOM-Zugriff und wird mit `node --test` getestet. Die Buchhülle (`book.js`) rendert Doppelseiten, Übergänge und Navigation; jede Sektion liefert Inhaltsblöcke, die ein Paginierer auf Seiten verteilt.

**Tech Stack:** HTML, CSS, JavaScript (ES2022-Module), Node 24 für Tests (`node --test`), Google Fonts (Cormorant Garamond, IM Fell English SC), keine Frameworks, keine npm-Abhängigkeiten.

**Spec:** `docs/superpowers/specs/2026-11-07-forever-journey-design.md` (Abschnitt 4 und 6), Datenvertrag `docs/superpowers/specs/2026-11-07-data-contract.md`, Optik-Referenz `docs/superpowers/specs/2026-11-07-forever-journey-mockup.html` (CSS-Variablen, Papier, Einband, Lid-Übergang dürfen übernommen werden).

## Global Constraints

- Seite liegt im Repo-Root: `index.html`, `assets/css/`, `assets/js/`; Daten relativ (`data/…`, `shots/…`), damit sie unter `https://<user>.github.io/ForeverJourney/` und lokal per `python -m http.server` funktioniert.
- Keine externen Skripte außer Google Fonts; Bilder nur aus `shots/` oder dem Arsenal-Render (nur per URL).
- Alle Texte Deutsch. Zeiten in Spielerzeit: `ts + meta.utcOffset`, formatiert als UTC des verschobenen Werts.
- Char-Wechsel und Rückweg zum Register: Lid-Übergang (zu, Prägung, auf; ~2,5 s). Innerhalb eines Kapitels: Überblenden 250 ms. Eselsohren blättern vor/zurück.
- Jede Doppelseite hat eine URL: `#/` (Register), `#/c/<id>` (Kapitelanfang), `#/c/<id>/<section>/<n>` (Seite n ≥ 1 der Sektion). Sektionen: `diary, gallery, deaths, levels, dungeons, gold, crafts, companions, iconic, journey, fun`.
- Credits: Vorwort im Register und Fußzeile jeder Doppelseite: „Daten aufgezeichnet mit dem Addon MyCharForever von Devchris“ mit Link `https://www.curseforge.com/wow/addons/mycharforever-an-automatic-character-chronicle`.
- Unter 820 px Breite: Seiten untereinander, kein horizontales Scrollen, Lid-Übergang durch Überblenden ersetzt.
- `show_companions`: die Gefährten-Sektion entfällt, wenn `state.companions` fehlt (das Tool entfernt sie bei `show_companions = false`, Tool-Plan Task 6).
- Tests: `node --test tests/site/`.

## Review Focus

1. Charakter-JSON mit leeren Listen (frischer Charakter, erste Sitzung, keine Screenshots): jede Sektion rendert eine sinnvolle Leerseite statt zu scheitern. → Task 4 (`test_diary_empty_record`), Task 6 (`test_sections_handle_empty`).
2. Hash-URL auf eine Seite, die es nicht mehr gibt (Sektion gekürzt, Charakter `retired` und gelöscht): Seite fällt auf Kapitelanfang bzw. Register zurück. → Task 1 (`test_parse_hash_invalid_falls_back`), Task 3 (`test_resolve_route_clamps_page`).
3. Arsenal-Render-URL lädt nicht (Charakter unter Stufe 10, Blizzard-Änderung): Porträt fällt zur Laufzeit auf Addon-Porträt oder Platzhalter zurück. → Task 3 (`test_portrait_fallback_chain`).
4. Ein Tag mit sehr vielen Ereignissen (Dungeon-Abend mit 40 Screenshots): Paginierer teilt ihn über mehrere Seiten, ohne einen Block abzuschneiden oder eine Endlosschleife bei einem Block, der allein größer als eine Seite ist. → Task 4 (`test_paginate_oversized_block_gets_own_page`).
5. `journeySegments` mit Punkten außerhalb 0..1 oder auf unbekannter `mapID`: Karte zeichnet nur gültige Segmente, Rest wird ignoriert. → Task 8 (`test_segments_skip_invalid_points`).

### Task 4: Tagebuch und Paginierung

**Files:**
- Create: `assets/js/diary.js`, `assets/js/paginate.js`, `assets/js/sections/diary.js`, `assets/js/sections/index.js`
- Test: `tests/site/diary.test.mjs`, `tests/site/paginate.test.mjs`

**Interfaces:**
- Produces (`diary.js`): `buildDays(record) -> Day[]` mit `Day = { key: 'YYYY-MM-DD', date: string, zones: string[], playedSeconds: number, items: Item[] }`; `Item = { time, kind: 'level'|'death'|'dungeon'|'guild'|'iconic'|'achievement'|'drop'|'gold'|'zone'|'journal'|'shot'|'session', text: string, level?: number, shot?: ShotEntry, quote?: string }`. Quellen: `lists.events` (Typen `LEVEL_UP`, `DEATH`, `ZONE_FIRST_VISIT`/`firstVisitedZones`, `GOLD_MILESTONE` falls vorhanden), `lists.dungeons`, `lists.journal` (`auto` → `quote`), `lists.worldDrops`, `shots`, `lists.sessions` (Spielzeit und Zonen des Tages). Tage ohne Items und ohne Session entfallen. Sortierung nach `time`.
- Produces (`diary.js`): `sentence(item: RawItem, record) -> string` – regelbasierte deutsche Sätze, erste Person, Beispiele (exakt): LEVEL_UP → `Stufe 10 erreicht.`; DEATH mit `cause: 'fall'` → `Gestorben: Sturz.`; mit `cause: 'drowned'` → `Gestorben: ertrunken.`; mit Gegner `data.killer` → `Von <killer> getötet.`; ohne Ursache → `Gestorben.`; Dungeon vollendet → `<name> abgeschlossen (<dauer>, <n> Tode).`; nicht vollendet → `<name> betreten, nicht beendet.`; Zonen-Erstbesuch → `Zum ersten Mal in <zone>.`; Weltdrop → `Gefunden: <item>.`; Gildenbeitritt → `Der Gilde <guild> beigetreten.`
- Produces (`paginate.js`): `paginate(blocks: Block[], pageHeight: number, measure: (block) => number) -> Block[][]` – füllt Seiten der Reihe nach; ein Block, der allein höher als `pageHeight` ist, bekommt eine eigene Seite (kein Abschneiden, keine Endlosschleife); `Block = { el?: Node, kind: string, height?: number }`. `measureInDom(container: HTMLElement) -> (block) => number` (hängt `block.el` unsichtbar ein, liest `offsetHeight`).
- Produces (`sections/diary.js`): `buildDiaryPages(record, ctx) -> Page[]` mit `Page = { title: string, el: Node }`; `ctx = { utcOffset, pageHeight, measure }`. Erste Seite der Sektion trägt die Überschrift „Tagebuch“, jeder Monat beginnt mit einer Zwischenüberschrift (Monatsname + Levelspanne).
- Produces (`sections/index.js`): `buildSections(record, entry, ctx) -> Record<string, Page[]>` – ruft alle Sektions-Builder auf (Task 4–8 ergänzen ihre Einträge hier); Sektionen ohne Daten liefern `[]`.
